# {{$frontmatter.order}} {{ $frontmatter.title }}

公告和通告被视为事件/紧急情况/网络中的所有参与者查看发布到组的所有公共信息的一种方式。从这个意义上说，它们被可视化为山顶广告牌或紧急运营控制中心墙上的公告板。

每个人都必须看到的信息应发布在那里。信息会被添加和删除。空间有限。在信息变得过于拥挤以至于无法让任何人看到所有内容之前，只能发布有限数量的信息。因此，信息应该被发布、更新和清理，以保持大广告牌整洁并与当前每个人需要知道的内容同步。不应该被过时的信息弄得杂乱无章。

这可以在 APRS 显示系统中实现为"公告屏幕"。每个人都有这个屏幕，任何人都可以在这个屏幕上发布或更新行。在任何时刻，网络中的每个人都看到完全相同的屏幕。一切都以完全相同的方式排列和显示。因此，世界各地的每个人都在看同一个山顶广告牌或公告板。对于谁在什么时间以什么顺序看到什么信息，不存在歧义。

为了实现这一点，应考虑以下几个问题：

- **排序：** 公告/通告几乎总是多行的，可能会以不同顺序到达。在发布到公告屏幕之前必须进行排序，并且当每个新行到达时可能需要重新排序。这包括按发起呼号和公告/通告 ID 排序。
- **替换：** 发送公告/通告的站点可以发送新行来替换之前发送的行，重用原始的公告/通告 ID。（注意：只需要重新发送替换行，不需要重新发送整个公告/通告）。收到与来自同一站点的已接收行具有相同公告/通告 ID 的新行时，应导致现有行被覆盖（替换）。
- **清除：** 用户应该能够在阅读后从公告屏幕清除任何或所有公告/通告。任何仍然有效的公告/通告将由于其冗余重传的方式而在适当时候重新出现。
- **提醒：** 在收到公告屏幕的任何新行或替换行时，应发出警报并定期重新响起，直到用户确认。因此，这些重要信息被"推送"给操作员。没有理由不了解当前的公告/通告状态——这在 APRS 事件的匆忙和危机场景中非常重要。
- **日志记录：** 旧的公告/通告应按顺序记录在 APRS 日志文件中，以防后续需要。
