# {{$frontmatter.order}} {{ $frontmatter.title }}

当符号表标识符为 `0`-`9` 或 `A`-`Z`（或仅压缩位置数据的 `a`-`j`）时，符号来自备用符号表，并叠加有标识符（作为单个数字或大写字母）。

例如，在非压缩位置报告中：

```
@092345z4903.50N3 07201.75W>...
```

纬度后面的数字 `3` 将导致数字 "3" 叠加在 "汽车" 图标上（注意：由于符号被叠加，此处的 `>` 符号代码来自备用符号表）。

类似地，要在压缩位置报告中为 "汽车" 图标叠加字母 "B"，报告看起来像：

```
=BL!!<*e7 >7P[
```

但是，在压缩位置报告中，不允许使用数字符号表标识符（`0`-`9`）——压缩位置从不以数字开头。如果需要数字叠加，报告必须改用小写字母（范围 `a`-`j`）作为符号表标识符。小写字母然后映射到数字 `0`-`9`（即 `a=0`、`b=1`、`c=2`、`d=3` 等）。

因此，在压缩位置报告中：

```
=d5L!!<*e7 >7P[
```

字母 `d` 映射到叠加字符 "3"。

如上所述，并非备用符号表中的所有符号都可以通过这种方式叠加——可以叠加的符号在附录 2 中标记为 `[可叠加]`。这意味着它们能够接受叠加，但不一定需要有叠加。因此，例如，以下报告使用了备用符号表中的汽车符号，但没有显示叠加：

```
@092345z4903.50N\07201.75W>...
```
