# {{$frontmatter.order}} {{ $frontmatter.title }}

APRS 协议定义了许多不同的数据格式，但它无法预见程序员可能希望发送的每一种可能的数据类型。用户自定义数据格式旨在填补这些空白。在此系统下，程序作者可以自由选择发送任何格式的数据。

AX.25 信息字段中的数据由一个三字符的头部组成：

- `{` — APRS 数据类型标识符。
- `U` — 一个字符的用户 ID。
- `X` — 一个字符的用户自定义数据包类型。

APRS 工作组将向有需要的程序作者发放用户 ID。

> [请注意，可用的用户 ID 数量有限，因此除非确实有需要，否则请勿申请。工作组可能会在发放字符之前要求你说明需求。如果只需要一两种数据格式，可以从用户 ID 池中发放]。

出于实验目的，或在获得用户 ID 之前，任何人都可以使用 `{` 作为用户 ID 字符，无需事先通知或批准（即以 `&#123;&#123;` 开头的数据包为实验性数据包，任何人都可以发送）。

**重要提示：** 虽然对用户自定义数据的性质没有限制，但强烈建议将其表示为可打印的 7 位 ASCII 字符形式。

## 用户自定义数据格式

```
{   用户 ID U   用户自定义数据包类型 X   用户自定义数据（建议使用可打印 ASCII）
字节数: 1       1                  1                                  n
```

示例
```
{Q1qwerty   用户 ID = Q，用户自定义数据包类型 = 1。
{{zasdfg    用户 ID 未定义（实验性），用户自定义数据包类型 = z。
```

这被设想为作者进行实验和构建特定于其程序的功能的一种方式，而不会出现非标准数据包导致其他作者的程序崩溃的危险。为了与 APRS 协议的精神保持一致，鼓励作者公开这些格式。APRS 工作组将维护一个网站，定义所有已分配的用户 ID，以及作者提供的数据包格式，或指向作者自己定义其格式的网站的链接。

通常，使用此方法的所有格式都被视为可选格式。任何程序都不需要解码这些数据包，且必须忽略任何它无法解码的数据包。但是，将来其中一些格式可能被证明对整个 APRS 社区具有足够的实用性和趣味性，以至于它们将被明确包含在 APRS 协议的未来版本中。
